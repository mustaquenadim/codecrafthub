# Bolt prompt for the CodeCraftHub dashboard

Copy everything inside the box below into Bolt.new or Bolt.diy as a single prompt.

```text
Build a single-file admin dashboard called "CodeCraftHub" as ONE self-contained index.html file with all HTML, CSS, and vanilla JavaScript inline. Do not use React, a build step, npm packages, or external CSS/JS frameworks. Use only the browser's fetch API.

BACKEND (already running, do not create or mock a backend):
const API_BASE_URL = "http://localhost:5000/api/courses";
Put this constant at the top of the script so it is easy to change.

API CONTRACT (follow exactly):
- GET    {API_BASE_URL}          -> 200, JSON array of courses
- GET    {API_BASE_URL}/stats    -> 200, {"total": number, "by_status": {"Not Started": n, "In Progress": n, "Completed": n}}
- GET    {API_BASE_URL}/:id      -> 200 course, or 404 {"error": "..."}
- POST   {API_BASE_URL}          -> 201, created course
- PUT    {API_BASE_URL}/:id      -> 200, updated course
- DELETE {API_BASE_URL}/:id      -> 204 No Content with an EMPTY body (do NOT call response.json() on this response)
- Send POST and PUT bodies as JSON with the header "Content-Type: application/json".
- Every error response has the shape {"error": "message"} with status 400, 404, or 500. Show that message to the user.

COURSE FIELDS:
- id (number, generated by the server, read-only)
- name (string, required)
- description (string, required)
- target_date (string, required, format YYYY-MM-DD; use <input type="date">)
- status (string, required, exactly one of: "Not Started", "In Progress", "Completed"; use a <select>)
- created_at (ISO timestamp, generated by the server, read-only)

FEATURES:
1. Header with the title "CodeCraftHub" and the subtitle "Personalized Learning Dashboard".
2. Stats bar with four cards: Total, Not Started, In Progress, Completed, loaded from /stats and refreshed after every create, update, or delete.
3. Course form to add a course (name, description, target date, status). Validate on the client that all fields are filled before sending. A submit button reads "Add Course".
4. Edit: clicking "Edit" on a row fills the same form with that course, changes the button to "Update Course", shows a "Cancel" button, and sends a PUT on submit.
5. Course table with columns ID, Name, Description, Target Date, Status, Created, Actions (Edit and Delete buttons). Show the status as a colored badge (grey = Not Started, amber = In Progress, green = Completed). Format created_at as a readable local date.
6. Delete asks for confirmation with confirm() before sending DELETE, then removes the row.
7. Search box that filters the table by name or description, and a status dropdown filter ("All" plus the three statuses). Filter on the client.
8. A "Refresh" button that reloads courses and stats.
9. Loading state while requests are in progress, and an empty state message "No courses yet. Add your first course above." when the list is empty.
10. Toast or alert banner messages for success ("Course added", "Course updated", "Course deleted") and errors. If fetch itself fails (server offline or CORS), show: "Cannot reach the API at http://localhost:5000. Make sure the backend is running."

CODE QUALITY:
- Use async/await with try/catch around every request, and check response.ok before reading the body.
- Escape user text before inserting it into the page (no raw innerHTML with course data) to prevent XSS.
- Clean, modern, responsive layout that works on mobile and desktop, with a CSS-variable color theme.
- Add short comments explaining each section of the JavaScript.
- Load the courses and stats automatically when the page opens.
```

## After Bolt generates it

1. Preview the dashboard in Bolt. If the preview can't reach `localhost`, allow the browser's "local network access" prompt, or go straight to step 2 and test the downloaded file.
2. Download or copy the generated `index.html`, and save it in this folder as `dashboard.html`.
3. Start the backend with `npm start`, then open `dashboard.html` in your browser.
4. Add a course, edit it, change its status, search and filter, then delete it. Check that the stats cards update each time.
5. Keep both this prompt and the generated HTML. The final assessment asks for the HTML code from your Bolt session.
